# Rhythm Studio — 自动节奏演出原型

独立页面 `/rhythm-studio?project=…`，从 Motion Studio 的“节奏场景”入口进入。
同一份歌曲工程可同时拥有歌词海报和节奏演出；两套设计不会互相覆盖。

## 首版范围

- NEON RUN：三轨透视道路、程序化柱阵、音符、判定线和命中光环。
- 已有拍点/鼓点自动生成谱面；疏朗、均衡、密集三档。
- 自动 Perfect 与连击显示明确标记为程序演出，尚不提供真人操作或难度评级。
- 种子控制轨道序列和环境构件；接近时间只改变预判距离；偏移只改变节奏事件。
- 字幕在屏幕平面独立排版，复用词级过光；不追随相机、不调整歌词时间。
- 横竖屏预览；1–60 秒片段导出，360p/720p，30 FPS，保留原曲音频。

## 模块与数据流

`project.analysis → buildRhythmChart → RhythmScene(time) → RhythmVideo → Remotion/FFmpeg`

1. `rhythm-model.ts`：纯函数生成 `{id,time,lane,strength,source}` 事件，按时间排序、合并过近事件。没有检测数据时不伪造 BPM 网格。
2. `rhythm-scene.ts`：Three.js 场景；固定镜头、共享几何和材质、柱阵实例化、固定音符池。所有变换根据绝对歌曲时间计算，拖动、反向查看和片段导出无须从头模拟。
3. `rhythm-video.tsx`：Remotion 组合、HUD、3D 画布和独立字幕区域。WebGL 不可用时显示错误，导出直接失败，不生成空白的“成功”视频。
4. `rhythm-studio.ts`：选歌、已有音频缓存、设置草稿、显式保存、预览和导出。Three.js 只随新页面加载，不加入现有 Motion Studio 浏览器包。

`GET/PUT /api/motion/rhythm`（本地）或 `/api/cloud-motion/rhythm`（云端）保存
`*_rhythm_settings.json`，包含版本、种子、密度、接近时间、偏移、主题、字幕与画幅设置。
云端继续使用原账号鉴权、任务归属检查和用户私有 R2 前缀，重启可恢复，不新增用户数据库。

`POST …/render` 新增 `scene: "rhythm"`。后端读取已保存设置并快照工程与参数，
使用 `RhythmStage` 组合渲染；原 `LyricPoster` 组合继续用于海报。复用已有队列、取消、
状态与私有下载接口。3D 导出共享单个渲染名额，排队期间仍可取消，避免多个用户的软件 WebGL 同时占满内存。云端无 GPU 时使用 Chromium 软件 WebGL，实际速度需按部署环境测量。

## 质量边界与下一步

首版只消费现有分析结果，不宣称“检测拍点一定准确”。段落名称只使用工程已有数据。
目前段落名称可显示，空间采用一套连续规则；自动弯道、长条音符、多场景段落编排、
局部谱面编辑和真人可玩性检查留到后续，先验证 20–30 秒副歌的卡点、可读性与渲染成本。

验证覆盖谱面确定性、密度、偏移、缺失数据、反向跳转、跨用户隔离、设置恢复，
并用实际 Chromium/FFmpeg 导出检查 3D 几何、运动帧和音轨。
