# 动效音频分析

音频分析负责音乐事件和连续强度；歌词对齐负责字词触发时间。自动排版仍需要文字测量、字体与布局规则，自动动画需要模板和事件映射。本次完成数据基础及现有流程接入，不宣称完成自动排版或 pdoom 主流程迁移。

## 已接入的流程

- 歌曲导入/处理：词级对齐（或复用对齐 JSON）后，分析原曲，生成 `<song>_analysis.json`，写入工程 `analysis`，再生成字幕。
- 已有歌曲：歌词编辑器“分析音频”按钮启动后台任务，状态独立于 CTC；重复点击复用当前任务，完成后保留未保存的歌词编辑。
- 离线导演：复用同一分析缓存，不再误把伴奏当作独立鼓轨。
- Suno 乐段标签补充后更新剪辑候选，无需再次分析音频。

缓存按原曲 SHA-256、算法版本、采样设置和 Librosa 版本判定；写入采用临时文件替换。内容、版本或参数变化时重算。`POST /api/audio/analyze` 接受 `json_path`、可选 `force`，返回 `task_id`；`GET /api/audio/analyze/{task_id}` 返回 running/done/error。任务状态保存在进程内，重启后需重新提交（磁盘缓存仍有效）。

## 数据约定

所有时间单位为秒，来自原始混音时间轴。`envelopes` 默认 100Hz，包含归一化的 `rms/low/mid/high/flux`；归一化是每首歌曲、每个通道独立计算，因此不能据此比较不同歌曲的绝对响度。

`beats` 为节拍估计，`onsets` 为瞬态事件。`downbeats` 按 4/4 和低频强度推断，不代表识别真实拍号。`drum_hits` 的 kick/snare/hat 是 HPSS 后频段瞬态启发式分类，不是鼓乐器识别模型。评分是启发式权重而非校准概率；具体方法记录于 `metadata`。`section_candidates` 仅表示能量变化候选，主副歌等语义乐段仍来自歌词标签/人工编辑。

静音返回 BPM=0、空拍点/瞬态列表、零能量曲线；不生成虚构节拍。输入损坏或缺少原曲会明确报错，不自动使用人声或伴奏代替。

pdoom 适配层可读取现有 `analysis.bpm/beats/downbeats/energy_curve/drum_hits`，后续再使用 `envelopes` 驱动缩放、辉光、相机运动；字词动画继续读取原有歌词时间轴。

## 实歌验证

2026-09-30，本机《04tuZiDongV1》原曲：198.805 秒，估算 122.73 BPM、367 拍点、19,881 个 100Hz 采样点。强制重新分析耗时 13.565 秒，缓存读取 0.100 秒（不含浏览器每秒一次状态查询）。这是单机测量，不是服务器性能承诺。未对拍点、重拍和鼓类别进行人工逐项标注，因此不能据此宣称实歌识别准确率。

本地测试入口：`http://127.0.0.1:8767/?song=04tuZiDongV1`。使用独立工作区中的测试副本，不覆盖原项目歌曲文件。
